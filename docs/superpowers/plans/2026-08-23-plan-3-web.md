# Plan 3: Web App (FSD React client) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A playable browser client — login, lobby, the reference-design poker table, bank/banker flows, ledger and hand-audit views — talking to the Plan 2 server, with all card crypto running in the browser.

**Architecture:** Vite + React 18 + TypeScript in `apps/web`, Feature-Sliced Design. Tailwind v4 with hand-rolled shadcn-style primitives (no shadcn CLI). zustand store. The protocol client (`gameClient`) is the browser twin of the integration test's TestClient, reusing `@4am/mental-poker` + `@4am/shared` directly.

**Tech Stack:** Vite 6, React 18, react-router-dom 7, zustand 5, Tailwind v4 (@tailwindcss/vite), clsx, @noble/hashes (scrypt).

**Spec:** `docs/superpowers/specs/2026-08-23-4amcasino-design.md` (§7 UI, reference `docs/design/reference-table.png`)

## Global Constraints

- Design language per reference image: light `#eef2f7`-ish background, white surfaces, single indigo accent (`indigo-600`), red/slate card suits, rounded-xl, generous spacing. No green felt.
- Client derives `authKey = scrypt(password, '4am/auth/'+username)` and ed25519 identity from `scrypt(password, '4am/id/'+username)` — password never sent raw; identity secret never leaves the browser. Requires new `identityFromSeed(seed: Uint8Array)` in `@4am/mental-poker`.
- Hand keys persisted to `sessionStorage` keyed by handId (refresh-survival).
- Client verifies: every board_open (recover the card itself from share chain? — MVP: trust + transcript download), every betting transition via local engine replay, and DLEQ of shares it receives is server-verified; client-side verification of others' shares is a stretch goal, not MVP.
- Every commit message: conventional-commit style + `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>` trailer.

### Task 3: shared layer — api client, ws client, auth derivation, store

**Files:** `apps/web/src/shared/{api.ts, ws.ts, crypto.ts, store.ts, ui/*.tsx, lib/cn.ts}`

`crypto.ts` (exact):
```ts
import { scrypt } from '@noble/hashes/scrypt';
import { bytesToHex } from '@noble/hashes/utils';
import { identityFromSeed } from '@4am/mental-poker';
export function deriveAuthKey(username: string, password: string): string {
  return bytesToHex(scrypt(password, `4am/auth/${username}`, { N: 2 ** 15, r: 8, p: 1, dkLen: 32 }));
}
export function deriveIdentity(username: string, password: string) {
  return identityFromSeed(scrypt(password, `4am/id/${username}`, { N: 2 ** 15, r: 8, p: 1, dkLen: 32 }));
}
```
- `api.ts`: fetch wrapper with Bearer token from store; typed helpers for every REST route.
- `ws.ts`: singleton socket per token; reconnect w/ backoff; `onMessage` fan-out.
- `store.ts` (zustand): `auth {token, userId, username, identity}` (token+username+identity secret persisted to localStorage), `room {state: room_state payload, chat: ChatMsg[]}`, `hand {handId, mySeat, myCards, board, betting, actionSeq, deadline, showdown, lastResult, abort}`.
- `shared/ui`: Button, Input, Card, Dialog, Slider, Badge, Spinner — shadcn-style Tailwind primitives.
- Commit: `feat(web): api/ws clients, password-derived identity, zustand store, ui kit`

### Task 4: gameClient — the browser protocol engine

**Files:** `apps/web/src/shared/gameClient.ts` (+ unit test with a mock socket `apps/web/test/gameClient.test.ts`)

- Unit test: feed a scripted message sequence through a fake socket; assert outbound messages are correctly signed/shaped and store updates (2 cards decoded, board accumulates).
- Commit: `feat(web): browser mental-poker game client`
