# Zeus UI and end-to-end UAT — 6 September 2026

## Result

The application now uses the official Zeus UI 0.2.3 SDK and tokens from
[myzeusui.com](https://myzeusui.com/). The shared sidebar, buttons, fields, charts,
settings, and account surfaces use the chosen white, neutral, Inter, and blue
system. Light/dark/cyber selectors are removed. Existing stored theme preferences
are ignored; the server's legacy profile field remains for client compatibility.
Card-back colors and the immersive night lounge are preserved.

The changes are local. This pass did not push, merge, or deploy.

## Environment and method

- Local Vite app on port 5174 and the actual Fastify/WebSocket server on port 8787.
- Isolated SQLite database, two browser accounts, no production data or balances.
- Chromium browser UAT with real registration/login, native form controls,
  independent authenticated browser contexts, cryptographic hand clients, and
  real HTTP/WebSocket traffic. API reads verified the outcomes of UI actions.
- Automated accessibility scans use axe WCAG 2 A/AA and WCAG 2.1 AA tags.
- Screenshots and manual visual inspection cover desktop and phone layouts.
- Software WebGL on this host is slow. The run verifies function and geometry,
  not native GPU frame rate.

## Bugs found and fixed

1. **TV poster with no playback:** React development StrictMode cleaned up the
   source, then reused the video element without reapplying its unchanged JSX
   attribute. Effect setup now restores the released source. The direct browser
   reproduction changed from `src=null`, `readyState=0` to a loaded 16-second video.
2. **Late fold error:** the final fold settled synchronously, but the client sent
   a recovery key afterward. It now sends that key only while multiple opponents
   still contest the pot. Three regression tests cover disclosure boundaries.
3. **Login bounced out of a newly entered room:** the previous success timer
   survived route unmount. It is now cleared; invitation handoff also clears the
   consumed pending code.
4. **Duplicate buy requests:** the out-of-chips dialog now recognizes a pending
   request after reload and guards repeat submissions while a request is in flight.
5. **Mobile overflow:** the lobby uses zero-minimum grid columns; replay header
   actions wrap and its board cards fit phone widths.
6. **Accessible cards and contrast:** card images have valid roles, empty spacing
   slots are hidden from assistive technology, small text and blind badges have
   sufficient contrast, and offline player labels no longer inherit whole-card
   opacity. Unlabeled form fields and login feedback were corrected.
7. **Visual inconsistencies:** obsolete cyber styling and fonts were removed;
   the public page uses an actual, labeled lounge preview instead of the old
   purple illustration, and the trust section uses the current neutral surfaces.

## Limits

This was local Chromium UAT, not a production rollout. Safari, physical phone GPU
performance, real wide-area latency, microphone audio quality, native sharing, and
platform fullscreen behavior were not exercised. Automated accessibility scans do
not replace screen-reader testing. The full existing regression suite covers
additional protocol and server flows, but this browser pass does not claim every
administrative operation was manually exercised.

Earlier nine-seat movement and card-sightline fixture coverage remains documented
in [world steering QA](2026-09-06-world-steering.md). This pass adds actual
multi-account local-server UAT and the Zeus UI checks above.
