# 3D control parity — local follow-up

This follow-up is local on `feat/3d-control-parity`. It has not been pushed or deployed. The preceding character update was published before the user's no-deploy instruction.

## Shared controls

`Table3DPage` now renders through the same `TablePage` room controller as 2D. The presentation changes; the role checks, dialogs, client handlers, and server endpoints are shared.

| Flow | Available in 3D through |
| --- | --- |
| Fold, check, call, raise, slider, quick amounts, all-in, pre-actions, ready/start, show cards | Existing `ActionBar` |
| Buy points, transfers, bank inbox, approvals, auto-approve, TV replays, minimum settle hands, 7–2 bounty, backup banker | Existing `BankControls` in Chips |
| Chat, quick phrases, stickers, unread count | Shared chat dialog and `ChatPanel` |
| Voice join/mute, video link | Header voice control and Table menu |
| Invites, watch-only link, spectator admission | Shared Table menu and dialogs |
| Standings, ledger, hand history | Shared Table menu |
| Sit out/return, host turn timer, theme, fullscreen, leave table | Shared utilities and Table menu |
| Take a seat, broke-player buy-in/watch, profile links, host/banker stand-up | Shared seat/broke state plus Players panel |
| Run-it-twice vote and two boards | Shared vote prompt and card rail |
| Hand result, winning cards, public reveals, share result, previous-hand recap/replay | Shared result, card rail, `LastHandStrip` |
| Private paid-peek offer/accept/decline and private results | Shared peek panel |
| Camera presets, character studio, reactions, targeted character interactions | Existing 3D controls |

The card rail remains readable without changing the camera. Opponent card meshes and the public rail use only voluntary shows and showdown reveals. Private paid-peek cards are never promoted into those displays. Dismissing the result now preserves cards and post-hand actions until the next deal. Large-card resize/close controls are visible on touch devices.

## Validation

- All-workspace TypeScript checks passed.
- Web unit tests: 8 passed, including two public-card privacy/precedence regressions.
- Web production build and server bundle passed. Existing lazy Three bundle size advisory remains.
- Headless Chromium control checks passed at 1440×1000, 390×844, and 375×667: menu permissions and timer lock, Escape/focus return, chat and stickers, enlarged cards, signed call, signed run-it-twice vote, two runouts, result dismissal preserving the hand, signed voluntary card show, paid-peek offer/accept/decline, ready/start, sit out, invites, watcher admission, standings, voice state toggle, banker settings presence, purchase approval, transfer, buy-in, two-step stand-up, seat picker, broke-player watch flow, spectator permissions, disconnected betting/chat, and switching back to 2D with one leave/one join.
- The normal WebGL pass also checked both runouts and public reveals at 375×667, opened/closed the character studio, then switched to 2D and confirmed both scene/preview canvases were removed with no page errors.
- The broad control pass deliberately disables WebGL to exercise the fallback. Separate visual checks use real Three rendering in Chromium's software renderer. Desktop/mobile screenshots were inspected and the layout was refined.
- Iteration caught and fixed an off-screen mobile Chips menu, a WebGL fallback layer blocking the vote, and the mobile 2D link losing its accessible name when its text is hidden.

API calls and WebSocket sends were intercepted in a temporary local fixture. No real account, table, chip balance, admission, or voice session was changed. Game-message signatures and reveal proofs were generated using a temporary test identity/key. Voice transport and backend financial settlement were not end-to-end tested by this UI pass. No physical-device FPS claim is made. The temporary fixture is removed from the app before completion.

The earlier broad-suite integration timeout/SQLite teardown behavior is documented in `2026-09-06-3d-experience.md`; this follow-up does not change the backend.
