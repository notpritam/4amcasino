# Stable 3D viewport during actions

Local follow-up on `feat/3d-seating-motion`. No push or deployment.

## Cause and fix

The lounge grid sized its footer from its contents. Showing the raise controls changed the footer height, shrinking the canvas. The scene's resize observer then refitted the camera. Card reveals, a second runout, and private peek offers caused larger changes.

The control dock now has a viewport-based reserved height: up to 260px on desktop and 360px below 1100px wide, capped at 46% of the viewport height. Overflow scrolls inside the dock, with a stable scrollbar gutter and scroll anchoring disabled. Desktop action controls align to the top instead of stretching with taller card rows. Short windows no longer inherit the old 480px minimum page height that put the footer below the screen.

The camera still responds to actual window resizing. Game state changes no longer resize its canvas.

## Verification

Browser checks used the existing temporary local fixture with intercepted API/WebSocket calls and test identities. No real table or account was modified. The fixture was removed after verification.

- Layout and control checks at 1440×1000, 1280×720, 1024×768, 768×1024, 390×844, 375×667, 320×568, and 844×390.
- At each size: idle, own turn, pending send, another player's turn, own turn again, folded, two-runout result, incoming peek offer, scrolling to controls, and ready check. Scene bounds stayed identical across all ten states. The footer remained within the window, with no document-level horizontal overflow.
- Keyboard adjustment of the raise slider, signed call, Call any pre-action, peek decline, Show cards, and ready confirmation remained usable, including controls reached by scrolling on short screens.
- Actual WebGL checks at desktop and phone sizes verified unchanged canvas bounds, camera position, and aspect ratio across those states. Live window resizing updated the canvas and projection correctly.
- Manually orbited camera framing survived a turn transition.
- Screenshots were inspected for both turn states on desktop and phone.
- `npm run typecheck`: all workspaces passed.
- `npx vitest run apps/web/test`: 106 tests passed.
- `npm run build --workspace @4am/web`: web build and server bundle passed; the existing lazy Three chunk size advisory remains.

These browser checks use Chromium's software WebGL renderer and mocked transport; they do not establish physical-device performance or live multiplayer coverage.
